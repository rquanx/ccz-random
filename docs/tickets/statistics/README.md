## 共同约束

- 统计数据只来自结构化结果快照，不从结果图或控制台文本识别。
- 默认统计口径为最终结果。
- 不同规则配置默认不隐式混合统计；需要通过“全部规则汇总”显式查看跨规则总体。
- 规则名称不是唯一标识，必须使用配置快照指纹。
- 3 人和 7 人使用不同且明确的武将位置分母。
- 多个个人天赋必须逐项保存和统计。
- 未知项不得静默丢弃。
- 技术诊断信息继续写日志，不进入统计界面。
- 所有删除、清空操作必须二次确认。
- 统计口径和规则维度是独立筛选轴；必须同时支持“全部规则看总体”和
  “指定规则/按规则分组查看”。
- 规则配置以 `rule_snapshot_hash` 作为唯一统计身份，不能只按规则名称筛选。
- 总览的存档数、状态数和平均尝试次数按
  `(run_id, round_id, slot)` 去重；尝试次数才按 `attempt_id` 计数。
- `current_run/current_round` 没有上下文时必须禁用或提示，不能静默回退到最近一次。
- 结果发布状态必须在真实发布完成后更新；结果图失败不能覆盖已确认的存档结果。
- 统计模块的“已完成”总览数字按存档任务去重；“全部已完成”和“全部尝试”
  的明细、失败原因和分布允许按尝试记录统计，必须在页面显示当前口径。
- 规则哈希不能擅自改变数组顺序语义；有序数组保序，无序集合由规则 schema
  明确声明后再排序。

## 规则维度验收矩阵

| 维度 | 是否跨规则合并 | 是否显示规则信息 | 分母 |
| --- | --- | --- | --- |
| 当前规则 | 否 | 当前规则名、版本、指纹 | 当前规则样本 |
| 指定规则 | 可多选，按所选规则合并 | 所选规则名和指纹 | 所选规则样本 |
| 全部规则汇总 | 是 | “跨规则汇总”、规则数、样本数 | 合并后的实际位置 |
| 全部规则分组 | 否，分别展示 | 每组规则名、版本、指纹 | 各组独立计算 |
