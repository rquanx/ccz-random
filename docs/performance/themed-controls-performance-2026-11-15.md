# 控件统一后的性能检查（2026-11-15）

## 结论与处理

ttk 控件首次创建略慢；主题配置自身没有形成瓶颈。高频操作中，原先人物翻页、结果图模式切换都会销毁并重建整页复选框，值得优化。

已让规则人物选择、结果图人物选择复用最多 42 个复选框。翻页只切换名称和人物变量；模式切换只更新禁用状态；筛选结果变少时隐藏剩余控件。人物变量仍按姓名独立保存，全选、清空、跨页选择及搜索不改变原有语义。

## 测量方法

- 使用项目 Windows Python，在独立后台桌面实际创建控件并完成布局，不影响用户前台窗口。
- 基线为 `81dbdb8`，对比当前包含 ttk 风格统一和本次复用优化的工作区。诊断进程通过导入器读取基线的六个相关模块，不切换分支或覆盖工作区文件。
- 使用 2.2 版的实际 130 人人名；规则启用全部随机人物采集，人物弹窗每页 42 人。
- 前后版本分别启动三个进程，按 ABBAAB 顺序交错执行；每个进程运行六轮，丢弃首轮。弹窗指标各 15 个样本，翻页/模式切换各 450 个样本，搜索 90 个样本。
- 最终对比期间不同时运行测试集。主窗口禁用游戏定位、后台线程和数据包更新，使用临时设置目录；没有启动游戏或写入真实历史数据。
- 弹窗、翻页和搜索统计同步操作加 `update_idletasks()` 的布局耗时。不是鼠标到屏幕显示的完整延迟，也不是 EXE 冷启动耗时。主窗口指标包含构建、首次事件处理、销毁及对象清理。

## 最终实测

单位为毫秒，均为中位数；基线为统一风格前，当前为统一风格并完成复用优化后。

| 操作 | 基线 | 当前 | 判断 |
| --- | ---: | ---: | --- |
| 主窗口构建、布局和关闭 | 255.11 | 281.48 | 增加约 26 毫秒，约 10% |
| 规则设置打开 | 450.07 | 458.19 | 基本持平 |
| 评分人物弹窗首次打开 | 44.12 | 83.72 | ttk 首次创建有额外开销 |
| 评分人物翻页 | 42.10 | 3.84 | 减少约 91% |
| 结果图人物弹窗首次打开 | 40.48 | 74.72 | 增加约 34 毫秒 |
| 结果图人物翻页 | 41.58 | 3.81 | 减少约 91% |
| 结果图模式切换 | 41.75 | 0.37 | 减少约 99% |
| 结果图人物搜索/恢复 | 111.57 | 52.06 | 减少约 53% |

当前人物翻页 P95 分别为 7.08 和 6.44 毫秒，模式切换 P95 为 0.56 毫秒。搜索 P95 仍有 111.27 毫秒，首次规则设置打开约 0.46 秒，不能据此声称所有操作都已无延迟。

主题首次初始化由 0.172 增至 0.255 毫秒；缓存后的调用约 0.154 微秒，没有必要继续微调主题配置。

重复翻页、模式切换和搜索前后，评分人物弹窗始终 58 个控件，结果图人物弹窗始终 61 个控件；没有观察到控件数量累积。该检查不等于完整原生内存泄漏检测。各轮未捕获到 Tk 回调异常。

首次弹窗增加的几十毫秒目前可接受，优先保留视觉一致性。后续如果仍感到明显卡顿，应优先分析规则设置首次打开和搜索触发布局的耗时，而不是继续减少 ttk 样式配置。

```powershell
./.venv-win10-py314/Scripts/python.exe -m tools.diagnostics.benchmark_themed_controls --baseline-ref 81dbdb8
```

原始样本与汇总：`artifacts/ui-performance/themed-controls-optimized/comparison.json`。

新增回归覆盖人物跨页和筛选后仍绑定正确变量、空搜索结果、恢复完整列表、连续 100 次翻页不增加控件数量。相关回归还覆盖结果图模式切换禁用状态、选择保存、规则保存和键盘操作。

针对性测试 34 项通过；项目环境完整单元测试 828 项通过，耗时约 213 秒。
