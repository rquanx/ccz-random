# 随机流程耗时优化（2026-11-10）

## 实际原因与改动

游戏会缓存已隐藏的“武将情报”窗口。原来的读档前清理逻辑向对话框发送关闭消息后，要求窗口句柄彻底销毁才继续；缓存窗口并不销毁，因此每轮耗满 1.5 秒上限。

现在以“窗口已销毁或已隐藏”为清理完成条件。可见窗口仍等待关闭，停止检查和最长等待保留；完整源存档内存校验、场景准备等待、NPC 与选项的独立点击以及失败重试均保留。

本次没有增加注入动作、内存补丁或直接调用游戏内部函数。实验中的列表通知、原生点击变更和异步确认均未采用，原生 C 源码已恢复。

## 实测

游戏版本为 2.20-1104 夜，使用临时游戏副本和真实三人随机流程。固定规则使兵种不合格，测量连续淘汰轮次；首轮标题读档不计入重复轮次中位数。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 重复随机中位耗时 | 5895.35 ms（4 轮） | 4406.6 ms（29 轮） |
| 窗口清理 | 约 1511 ms | 约 0.2–0.6 ms |
| 常规交互重试 | 0 | 0 |

重复随机耗时降低约 25.3%。优化后共完成 30 轮，首轮 8769.4 ms；首轮仍需要游戏启动、标题读档和场景准备，本次没有针对首轮提速。合格结果的面板采集、保存耗时不包含在此收益中。

额外丢弃首次 NPC 点击的 3 轮测试发生一次预期重试，恢复成功。测速前后原游戏 SV020.E5S 和 RS/S_00.EEX 摘要一致。

证据位于 `artifacts/random-performance/`：`baseline.json`、`load-substeps.json`、`cleanup-details.json`、`optimized-30.json`、`retry-recovery.json`。
