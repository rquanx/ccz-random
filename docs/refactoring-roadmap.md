# 渐进重构路线

`ccz_randomizer/app.py` 当前同时承担应用组合、Windows 原生控制、游戏会话、
检查流程、结果生成和主窗口职责。该文件已有大量真实游戏兼容逻辑，后续重构
应以保持行为和缩小单次改动范围为前提。

## 优先拆分方向

1. 原生控制适配层
   - 统一进程注入、窗口命令、菜单操作和错误码转换。
   - 对外返回结构化结果，诊断细节写入日志。

2. 游戏会话
   - 管理游戏进程生命周期、读档、保存、停止和异常恢复。
   - 保持沙箱模式与兼容模式使用同一会话接口。

3. 检查流程
   - 将三人、七人的兵种、个人天赋、兵种技能和宝物检查组织为可测试步骤。
   - 输入使用固定内存样本或结构化结果，避免单元测试依赖真实游戏。

4. 结果生成
   - 统一评分详情、单存档面板、汇总结果图使用的结构化结果对象。
   - 将文件发布和图片绘制与游戏控制分离。

5. 主窗口 Controller
   - 主窗口只负责用户操作、状态订阅和弹窗生命周期。
   - 多实例控制台继续使用独立状态模型，避免在 Tk 回调中嵌入调度逻辑。

## 实施约束

- 每次只迁移一个清晰边界，并为用户可观察行为增加或保留回归测试。
- 不借重构改变控制台文案、存档格式、规则配置 Schema 或结果目录结构。
- 涉及存档、剧情文件、进程生命周期和内存解析时，运行完整单元测试集，并
  保留真实游戏冒烟测试记录。
- 先建立接口和测试夹具，再移动实现；不一次性重写 `app.py`。
