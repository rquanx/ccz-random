## 2026-09-27 七人剧情连点

完整七人流程中，原有 80 次剧情连点采用每次 55 毫秒按下、95 毫秒
抬起后等待，实测 P50 为 13.636 秒。

隔离测试结果：

- 150 毫秒：2/2 成功，P50 13.636 秒。
- 145、140、135 毫秒：均 2/2 成功，P50 约 12.44 秒。
- 130、120、100、80 毫秒：全部失败，剧情没有推进到七人场景。
- 75 次、150 毫秒：20 轮中仅 17 轮成功，不能接入。
- 80 次、135 毫秒：20/20 成功，P50 12.403 秒。

正式流程第一批使用 80 次、135 毫秒；若七人场景仍未就绪，后续批次
自动回退原来的 80 次、150 毫秒节奏。单个七人候选预计节省约 1.2 秒，
同时保留原节奏作为兼容兜底。

## 已验证并接入

### 缩短第二次点击的尾部等待

现有第二次点击在鼠标抬起后仍固定等待 1200 毫秒，随后 Python 才开始
轮询兵种变化。诊断动作只改变这段尾部等待，第一次点击和两次独立输入
周期保持不变。首轮脚本遗漏了正式流程的场景等待，结果无法用于判断该
参数，已经作废。修正后的候选值为 0、300、600、900、1200 毫秒，
其中 1200 毫秒是原值对照组。

修正后的首轮结果全部成功：

- 0 毫秒：4/4，交互 P50 2.510 秒。
- 300 毫秒：4/4，交互 P50 2.822 秒。
- 600 毫秒：4/4，交互 P50 3.121 秒。
- 900 毫秒：4/4，交互 P50 3.426 秒。
- 1200 毫秒：4/4，交互 P50 3.726 秒。

0 毫秒相对原值每轮节省约 1.2 秒，下一步单独进行 30 轮压力验证。

30 轮压力验证结果：

- 成功 30/30，失败 0。
- 交互 P50 2.508 秒，P95 2.526 秒。
- 测试前后前台窗口和鼠标坐标一致。
- 测试结束后没有残留游戏进程，源存档 SHA256 恢复一致。

该优化已达到接入门槛。正式流程优先使用 0 毫秒尾部等待；若原生动作
报错或返回后兵种尚未变化，自动回退原 1200 毫秒点击路径。

场景等待首轮隔离测试：

- 读档后等待：0、300、600、900 毫秒均 0/3 成功，1200 毫秒 3/3。
  这段等待暂时不能缩短，标记为暂时跳过。
- 读档前等待：0、300、600、900、1200、1500 毫秒均 3/3 成功。
  读档前 0 毫秒继续完成 30/30 压力验证，因此正式流程已移除这段
  1.5 秒固定等待。

## 暂时跳过

### 合并两次许子将点击

已进行两轮后台验证：

- 持续使用同一组输入钩子，700、1000、1300、1600 毫秒间隔均为 0/6。
- 同一原生调用内重新建立输入周期，500、800、1100、1400 毫秒间隔
  仍均为 0/6。

两次点击必须由两个独立原生调用完成；继续压缩会改变游戏接受输入的行为，
不符合安全改动要求，因此暂时跳过。

### 从存档或内存直接读取七人特技

已对 13 个存档、150 个界面识别特技做原值和结构匹配，未找到稳定映射。
`0x6800` 区域不能可靠解释为七人六特技，现有直接偏移结果为空。误读会
直接改变筛选结果，因此暂时保留经过验证的游戏界面读取。

恢复条件：获得剧情推进前后的成对完整内存样本并找到稳定映射，或定位到
游戏解码特技数据的函数。

### 多游戏实例并行随机

并行实例需要隔离游戏目录、存档目录、剧情文件和结果写入，资源占用与
兼容风险较高。单轮固定等待仍有明显优化空间前，不进入生产实现。

### 常驻原生控制通道

目前主要耗时来自固定等待，而不是启动注入器本身。先完成合并交互基准；
只有注入器空操作基准证明进程和远程线程开销显著时再实现常驻通道。
