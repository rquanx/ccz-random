# ST-008 回归测试、性能测试与发布验收

## 目标

验证统计模块的数据正确性、历史兼容性、交互行为和可接受性能。

## 自动化测试

- 数据库初始化和迁移幂等。
- 3 人、7 人分母。
- 多个人天赋。
- 兵种技能与个人天赋分离。
- 未知兵种、特技、宝物和特性。
- 三种统计口径。
- 循环轮次最终结果去重。
- 不同规则配置隔离统计。
- 同名不同配置按配置指纹分组。
- 全部规则汇总与分组的样本数守恒。
- 原始快照与查询索引一致性。
- 合格率和失败原因。
- 删除、清空和导出。
- 图表过滤与明细结果一致。

## 固定夹具

使用真实日志、真实结果快照和已确认的内存解析样本构造测试夹具，不凭空构造枚举名称。

至少准备：

- 一个 3 人合格结果。
- 一个 7 人合格结果。
- 一个多天赋结果。
- 一个包含未知项的结果。
- 一个多轮循环结果。
- 一个包含失败尝试但最终合格的存档。
- 两个规则名称相同但配置内容不同的运行。
- 一个可清空并从结果快照重建的统计数据库。
- 一份只有最终结果、没有历史尝试明细的旧版数据库。
- 一组相同规则名称但不同配置的历史结果，并分别验证当前规则、
  指定规则、全部规则汇总和全部规则分组。
- 一组同一存档多次尝试、其中一次合格且最终发布的结果，验证总览按存档任务去重。

## 性能要求

- 打开统计窗口不阻塞主随机窗口。
- 常规历史查询不应逐条读取结果图片。
- 聚合查询优先使用数据库字段和索引。
- 明细超过预设数量时分页或分批加载。
- 图表刷新不重复执行相同查询。

## 发布验收

- 运行完整单元测试。
- 运行历史迁移测试。
- 运行统计查询和导出测试。
- 使用真实历史数据库做只读回归。
- 确认统计模块不修改游戏存档和结果图。
- 确认统计模块不增加控制台技术信息。
- 记录尚未覆盖的旧版本数据风险。
- 验证结果图生成失败、发布失败和回调重复/乱序时，最终结果状态仍正确。
- 验证统计模块使用共享历史数据库时，并发 worker 不会覆盖运行/轮次状态，
  发布确认不会串到其他存档，循环轮次不会混淆相同 slot。
- 在发布验收前明确列出“已实现、初版可用、未完成”的 ticket，不把初版 UI
  或单元测试通过等同于全部功能完成。
