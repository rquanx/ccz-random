# 弹窗打开响应性优化

## 发现与修改

历史窗口的数据查询原本已有后台线程，但主界面打开历史时先同步构造 `HistoryRepository`。构造会检查数据库、设置 WAL，旧版本还会压缩迁移和整理数据库；遇到锁或旧数据库时，窗口尚未出现就会阻塞界面。现在先创建窗口，在窗口自己的串行工作线程中初始化数据库，再查询第一页。初始化失败在窗口内显示错误，点击刷新可重试。已有窗口直接恢复并前置，避免重复创建控件和读取线程。

历史首屏的轮次卡片、结果卡片均改为每批一张，批次之间让出事件循环。取消旧页面和关闭窗口的行为沿用已有控制器；不改变历史内容、存档及数据库格式。

使用说明原先一次创建全部 11 页的 Text 和滚动条，现在仅创建当前页的内容，首次切换到其他页时才创建。创建后的内容保留，不重复插入。

规则评分网格原先在初始化、变量加载、启用状态变更、尺寸事件中反复整体重画。现在将这些请求合并到一次 idle 绘制，使用最终变量值；直接编辑与搜索仍保留即时更新。关闭网格会取消待执行的重绘。

## 测量

使用项目 Python，在独立后台桌面测量；通过 SQLite 只读连接备份游戏目录的约 18 MB 历史数据库，所有查询与初始化均发生在临时副本上。不启动游戏、不修改真实历史数据。临时副本在测量前已初始化，因此下列数字不包含首次旧库迁移及等待数据库锁的耗时。

每种窗口测量四次，下表取后三次的中位数，单位毫秒。样本数量较少，Windows 调度和原生窗口绘制有波动；这些数字不是性能保证。构建耗时包含窗口创建和首次居中布局，心跳间隔包含同步打开及之后 450 毫秒的事件处理。

| 操作 | 修改前同步构建 | 修改后同步构建 |
| --- | ---: | ---: |
| 历史记录 | 58.59 | 53.20 |
| 规则设置 | 205.66 | 173.27 |
| 使用说明 | 81.76 | 43.39 |

历史心跳最大间隔的中位数为 134.55 → 112.79 毫秒，第二次复测为 124.81 毫秒，提升有限。第二次复测的规则设置和使用说明构建中位数分别为 167.68 和 40.57 毫秒。特效手册与常见问题没有改变创建逻辑，测量波动不足以推断性能变化。仍然存在首次原生控件创建与布局成本，不能据此宣称全部弹窗已无卡顿。

原始样本与剖析输出位于 `artifacts/ui-performance/dialog-open-before*`、`dialog-open-after*` 和 `dialog-open-profile*`。

复测：

```powershell
./.venv-win10-py314/Scripts/python.exe tools/diagnostics/benchmark_dialog_open.py --history-db <历史数据库路径> --output artifacts/ui-performance/dialog-open.json
```

## 回归范围

新增测试验证：数据库初始化被阻塞时窗口仍处理事件；初始化失败后刷新可重试；重复打开历史不会创建第二个窗口；说明内容随选中页按需创建且内容完整；评分网格重绘使用最终变量值、关闭后不执行遗留回调。原有历史筛选、编辑、分页复用、旧响应丢弃、规则编辑和居中定位测试继续验证。

最终完整单元测试 848 项通过，耗时约 208 秒。第一次完整回归发现特殊特技门槛的即时标签反馈被延迟，已恢复手动编辑时的同步刷新；规则加载期间仍合并重绘。修正后重新运行完整测试集通过。

本次没有测试真实游戏，也没有重新构建 EXE。
