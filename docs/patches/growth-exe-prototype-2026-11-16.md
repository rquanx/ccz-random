# 原 EXE 成长修复实验副本

2026-11-16，针对原版 SHA-256 为 `aece85339ff48c24e8d783d2d65766e8c9f7be00bd7389d38a8cad8f7cbd95a5` 的 2.20-1104 夜版。

## 副本与使用

整个游戏目录已经复制到仓库下 `artifacts/growth-exe-prototype/game/`，共 5402 个源文件，约 1.08 GB。没有使用指向原游戏的硬链接。

在该副本中直接运行 `Ekd5.exe`，不需要额外启动器。它与同目录的 `CCZFX.DLL` 配合工作。原 EXE 的备份是 `Ekd5.original.exe`；实验生成的第 15 栏存档仅用于本次自动化验证。

这不是纯单文件 EXE 补丁：EXE 已实际修改，但修复代码放在配套 DLL 内。不要只复制修改后的 EXE 而漏掉 DLL。原音效启动器仍可启动同目录的 `Ekd5.exe`，两者同时使用的兼容性尚未实测。

## 实现

直接改动原 EXE 的 5 个字节，将文件偏移 `0x6B58` 的导入库名从 `PSAPI.DLL` 改为等长的 `CCZFX.DLL`。没有移动节、修改入口或移动原程序尾部资源，避开了前一次新增 PE 节的启动失败。

配套 DLL 将原本唯一使用的 `GetModuleFileNameExW` 转发给真正的 PSAPI，再在游戏解包完成后安装补丁。安装前检查修改后 EXE 的完整 SHA-256 和各个目标位置的原始指令，版本不匹配则报告错误。

- 0～101 号仍访问原成长表。
- 102～214 号使用独立成长表。
- 接管成长记录获取、成长补正读取、通用成长补正修改。
- 拦截原生保存／读档；自动保存和恢复扩展记录。
- 新存档尾部增加 1582 字节成长数据和 32 字节索引，共 1614 字节。索引带格式版本、人物数、正文长度以及正文、成长数据、索引的 CRC32。
- 保存前备份原槽，生成带扩展的临时文件，刷新后替换；扩展保存失败则尝试恢复原槽。覆盖时使用引擎实际写入字节数，避免不断追加旧扩展。
- 读取无扩展的旧存档时清空高编号成长表，避免跨存档串值；扩展格式和载荷完整、但正文校验不匹配时，也清空高编号成长，交给原生引擎继续读档，以兼容原版回存。扩展本身损坏或文件读取失败仍取消读档。正文校验不匹配无法区分原版回存与正文损坏，此路径不保证原生正文完整性。

补丁代码按模块拆分在 `native/ccz_growth_patch.c`、`native/ccz_growth_storage.c` 和头文件中。没有改动随机工具的原有 Python 业务流程。

### 与未打补丁 EXE 的实际互读结果

2026-11-16，使用副本内未修改的 `Ekd5.original.exe`，确认原资格检查指令未安装钩子，以第 15 栏的有效扩展存档为夹具，分别运行以下独立进程测试。下表记录调整前结果：

| 操作 | 实测结果 |
| --- | --- |
| 原 EXE 刚读入扩展存档 | 可读入，143 号张绣基础 HP／MP 为 195／29 |
| 原 EXE 调用原生属性重算 | 恢复为 167／21，高编号成长不被识别 |
| 不重算、修改普通低编号成长字段后覆盖原槽 | 文件仍为 265374 字节，扩展载荷和索引校验仍正确，但正文校验失效；补丁版返回失败、状态 5，保留此前已加载人物记录 |
| 重算后覆盖原槽 | 同样保留旧尾部，正文校验失效，补丁版拒绝读档 |
| 不重算、另存到不存在的空槽 | 只生成 263760 字节正文，没有扩展；补丁版能读入，刚读入仍为 195／29，重算后为 167／21 |

覆盖原槽并非必然抹掉高编号成长载荷，而是保留了与新正文不匹配的旧扩展，触发调整前补丁的严格校验。随后按用户确认调整为：正文校验不匹配时丢弃高编号成长，按普通存档继续读取；不尝试恢复旧成长载荷。

调整后的四种回存场景均已重测通过：直接覆盖、修改普通成长字段后覆盖、重算后覆盖、另存空槽。补丁版均成功读取，清空此前已加载的高编号成长，原生重算为 167／21；再保存生成校验正确的新扩展，退出并重新启动后仍能读档、重算为 167／21。独立 C 存储回归增加到 42 项，覆盖失配时完整清空、扩展自身损坏仍拒绝、重新保存后恢复有效扩展等行为。

调整后完整 Python 单元测试 850 项通过。正常补丁存档的高编号道具成长、属性重算、覆盖保存、旧档清零和退出重启恢复也已重新通过真实游戏自动化回归；副本中的 DLL 已替换为此构建，EXE 无需再次修改。

测试通过调用真实引擎的读档、重算、保存函数完成。最终兼容回归没有替换业务函数或错误弹窗。没有操作实际升级／转职菜单，不能据此宣称每个菜单触发路径均已验证。测试后恢复副本 11～13 栏原文件，第 15 栏夹具未改变；输出样本和 `unpatched-compatibility-results.json` 留在 `artifacts/growth-exe-prototype/`。
