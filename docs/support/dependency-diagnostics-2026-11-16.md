# 随机无法使用：原生依赖检测

入口：常见问题 → 随机用不了？；主窗口 → 开始随机。

## 开始随机前的检查

每次点击“开始随机”都会在后台重新检测运行依赖，不缓存成功结果。按钮显示“正在检测依赖…”，检测期间拒绝重复启动；界面仍可处理其他操作。检测通过后继续原有随机流程和所选参数，不执行额外的兼容模式随机。

检测失败或超时时恢复开始按钮，并显示修复说明及对应架构的官方下载、复制地址按钮。用户安装或修复后可点“重新检测”，通过后继续刚才的随机操作；也可取消。依赖通过之前不执行随机启动时的游戏清理、源存档检查或 Worker 启动。

检测任务按需创建，完成后关闭轮询定时器，不增加主窗口空闲时的常驻轮询。窗口关闭后不接受迟到结果，不会因此重新启动随机。

真实依赖的后台冒烟检查约 625 毫秒完成，期间主窗口事件探针正常响应；该数据来自本机 Python 源码环境，不代表 EXE 解包或其他电脑的耗时。没有启动真实游戏。

## 日志证据

用户提供的 `fast_20261115_215312_worker1.log` 在载入 `utils/CvUtils.py` 时出现：

```text
ImportError: DLL load failed while importing win32ui: 找不到指定的模块。
```

仅凭这一条错误不能确定缺失的 DLL。检查本地配套运行组件的 PE 导入表后，确认 `pythonwin/win32ui.pyd` 是 x64，依赖 `mfc140u.dll`、`VCRUNTIME140.dll`、`VCRUNTIME140_1.dll` 和 `pywintypes314.dll` 等组件。MFC/VC++ 运行库缺失是需要重点检查的原因；组件文件丢失、架构不匹配也必须区分。

## 当前行为

- 后台子进程检查系统版本、系统架构、工具架构，以及 VC++/MFC DLL 的实际加载能力。
- 实际载入工具附带的 `win32ui.pyd`，不会用开发环境另外安装的 pywin32 掩盖组件缺失；同时检查 NumPy 和 OpenCV。
- 依赖有异常时不执行兼容随机，提供微软官方地址，支持打开链接、复制链接。用户自行下载、安装或修复，之后点击“再次测试”重新检测。
- 依赖通过后才执行原有兼容模式测试。合并读取标准输出和标准错误，运行期间遇到 DLL 加载失败也会给出相关指引。
- 组件文件缺失或架构错误提示重新下载完整工具，不把所有错误都认定成缺少 VC++。
- Windows 7/8/8.1 等不受当前工具支持的系统不推荐最新版安装包；明确提示系统不兼容及微软说明页。
- 检测结果通过临时 JSON 文件返回，兼容无控制台 EXE；子进程最多等待 30 秒。诊断窗口提前关闭时，不在依赖检查完成后继续启动游戏。

安装包架构按需要加载组件的工具进程选择，而不是根据游戏为 32 位就推荐 x86。例如，64 位 Windows 上的 x86 工具推荐 x86；ARM64 系统上模拟运行的 x64 工具推荐 x64。

本机使用真实配套组件完成独立子进程检测，VC++/MFC、win32ui、NumPy、OpenCV 均通过；检查了模拟缺失依赖时的真实界面布局。没有卸载本机运行库，也没有在用户故障电脑上验证安装后的结果。
