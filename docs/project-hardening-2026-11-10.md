# 项目优化落地（2026-11-10）

## 七项处理结果

| 优化项 | 本轮实现 |
| --- | --- |
| 发布脚本 | 禁止扫描旧游戏目录；必须通过 `-GameDir` 或 `CCZ_GAME_DIR` 指定目标。按明确 EXE 名选择本轮产物，构建前删除同名旧产物；构建及复制前分别校验内置数据包的非空游戏指纹；四项 EXE smoke 全部通过才复制；复制后校验 SHA-256。构建文件锁禁止两个发布进程同时操作同一工作区。 |

| 异步生命周期 | 共用 `WindowTasks`：后台只向队列回传，主线程执行 UI 回调；请求代次隔离、协作取消、关闭注销定时器、丢弃晚到结果。历史读取保留串行队列；上传支持取消；安装和存档写入继续收尾。兼容性诊断关闭后不强杀进程，以保留存档恢复机会，同一主窗口内禁止重复启动尚未收尾的诊断。 |
| 主模块拆分 | 上传/诊断拆到 `ui/support_controller.py`；结果与历史快照拆到 `workflow/result_snapshots.py`；两类运行时适配器拆到 `runtime/game_adapter.py`、`runtime/inspection_adapter.py`。保留 app 兼容入口；适配器显式接收本次 Worker 的服务依赖。 |
| 数据包热激活 | 新增深层只读 `ProfileContext`，技能名称、显示规则等消费者从统一入口读取；先准备完整快照，兼容变量刷新成功后一次发布引用；失败回滚模块绑定、共享字典和版本环境变量。旧快照持有者仍保留完整旧数据。 |
| 弹窗渲染 | 人员索引缓存搜索文本、人物天赋归一化结果；只有规则变化才重算特殊技能集合。卡片按行分批绘制，过期筛选停止继续绘制。宝物弹窗预建搜索索引，结果相同时保留控件和滚动位置；保留上一轮详情 Canvas 与设备分类合并渲染优化。 |
| 构建来源 | 删除 spec 中本机绝对路径；支持 `CCZ_RUNTIME_ROOT`，缺少必需模块时提前失败。提供已验证环境的依赖版本清单。构建摘要覆盖 resources、spec、打包脚本和原生资源；构建信息记录 Python/架构、依赖版本、数据包编号/修订/文件摘要，以及实际打包外部运行时逐文件 SHA-256。构建 ID 同时覆盖上述来源信息。 |

## 渐进改造保留边界

运行时适配器内部以及 `main`、规则编辑器仍有较长函数，本轮没有重新编写随机业务流程。旧模块常量仍作为兼容桥保留；统一快照已投入技能显示消费并负责激活发布，但尚未将每个旧模块常量替换为 Context 参数。这样可以继续按模块迁移，避免一次改动整个内存解析和规则系统。

跨进程锁文件不删除，保证所有等待者锁住同一文件；进程被杀后操作系统会释放锁。强制终止可能遗留私有 staging/临时文件，它们不参与后续安装，也不会被其他安装过程复用。

## 人员弹窗性能复测

使用相同的 126 名招募人物、17 名固定人物夹具，3 次测量取中位数。此前记录来自上一轮优化后的版本，本轮修正了分批渲染的就绪条件：必须出现快照中所有人物的卡片标题，不能仅以首张卡片出现作为完成。

| 指标 | 此前同夹具记录 | 本轮复测 |
| --- | ---: | ---: |
| 窗口同步构造 | 199ms | 49ms |
| 全部人物卡片就绪 | 322ms | 368ms |
| 8ms 心跳的最大事件延迟 | 196ms | 43ms |

全量绘制总时间略有增加，换来更短的单次阻塞及绘制期间的输入响应；不将分批绘制描述为全量绘制耗时全面下降。测量使用屏幕外的真实 Tk 窗口，排除 EXE 冷启动和常规居中动画；不同测量时段、系统负载和 Tk 定时精度都会影响数值。原始结果：`artifacts/project-hardening/ui-benchmark.json`。

## 本地构建

在 Windows x64、CPython 3.14.3（含 Tk）准备构建虚拟环境：

```powershell
py -3.14 -m venv .venv-win10-py314
./.venv-win10-py314/Scripts/python.exe -m pip install -r packaging/requirements-build.txt
$env:CCZ_RUNTIME_ROOT = 'D:\dependencies\tool.exe_extracted'
./tools/windows/build_release.ps1 -GameDir 'E:\game\ccz\曹操传加强版v2.20-1104夜' -RunTests
```

外部运行时需要原工具提取的 `PYZ.pyz_extracted`、模板和原生依赖等完整目录；`CCZ_RUNTIME_ROOT` 支持绝对路径或相对项目根目录的路径，未设置时兼容项目旁的 `exe-analysis/tool.exe_extracted`。这份外部输入不能仅靠 pip 重建，发布构建信息中记录了实际打包文件摘要，换机器时必须准备相同输入。

只构建并执行 smoke、不复制时使用 `-SkipCopy`。自定义 spec 时也必须通过 `-OutputName` 明确其输出文件名。

这些措施保证来源可追踪、缺依赖提前失败，不宣称在不同机器上生成逐字节相同的 EXE；构建时间、PyInstaller 和系统环境仍会影响最终二进制。最终交付以 EXE SHA-256 为准。
