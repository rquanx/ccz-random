# 规则评分与历史翻页优化

## 定位和实现

本轮关注弹窗、页签和翻页的通用迟钝感。使用真实历史数据库的副本，在 Windows 私有桌面运行 Tk 事件循环和 cProfile；不启动或操作游戏，不切换用户当前桌面。

规则编辑初次打开时，两次评分网格刷新合计创建了 2814 个 Canvas 项目，约耗时 76ms，包含未显示页面及视口外的项目。现在只绘制可见行与上下预留行；搜索仍匹配完整目录，滚动范围仍覆盖全部项目。滚动条、滚轮及程序滚动均通过 Canvas 的视口通知触发更新，只在可见行范围变化时重画。刷新前提交正在编辑的值，保持原始项目索引，避免滚动后修改错误项目或丢失输入。

历史页查询约 11–18ms，并非当前主要瓶颈。原有部分卡片每张单独一批、批间等待 8ms；现在保留每张一批、缩短批间等待为 1ms。每张后让出事件循环，继续保留卡片复用与过期请求取消机制。

曾实测每批最多三张、预算 6ms 的方案：历史下一页中位耗时从 441ms 降到 359ms，但心跳最大间隔的三轮中位数从 59ms 增至 102ms。因此未采用该方案，以减少单次停顿优先。中间实验报告保留在 `optimization-{before,after}-{1,2,3}.json`。

新增回归使用真实兵种目录，检查初始画面只创建部分项目、滚到最后可编辑、滚回顶部保留输入、搜索末项可读到新值。既有历史分批测试继续验证昂贵卡片不会阻塞后续输入事件。

## 验证方法

优化前后均使用实际打包 EXE，交替各运行三轮相同的 45 个操作场景，使用 `.tmp/ui-profile-data` 固定数据副本。每个场景统计目标就绪时间和 8ms 心跳最大间隔，并额外观察 120ms 延后绘制。最终测试报告位于 `artifacts/ui-performance/optimization-final-{before,after}-{1,2,3}.json`。

该验证不覆盖交互桌面 DWM 合成帧率、游戏运行时资源竞争或真实鼠标手感；“首次”是新进程首次打开，并未清除操作系统缓存。详情计时仍是窗口出现而非全部人物卡片绘制完成，本轮未修改详情渲染。

首次对照尝试曾在未修改的旧 EXE 中因原生下拉框未映射超时；重试成功。失败轮未计入结果，后台桌面测试不能据此宣称原生弹出控件在所有系统环境都没有问题。

优化前 EXE SHA-256：`03E1B2F2C9A7D45330AC235610DAF39ECFD246E0B0334255C94A550EE1451C82`。

最终 EXE SHA-256：`593778267F3A947A97843E68E93EECB9AFAD2D3F616C6AD043DB656EE886CA3C`。使用 `build_release.ps1 -SkipCopy` 构建，四项标准 EXE 冒烟检查通过，未复制到游戏目录。

规则编辑、特殊门槛、历史加载的 51 项针对性测试通过。最终版本完整单元测试 851 项通过（225.3s）；另一次中间方案的完整单元测试也通过，但性能取舍以最终 EXE 对照结果为准。

## 最终 EXE 对照结果

新旧各三轮、每轮 45 项操作均通过，未记录 Tk 回调错误。下表是三轮中位数，单位 ms；心跳列是各轮最大间隔的中位数，不能解读为所有轮次的最坏值。

| 操作 | 原就绪耗时 | 新就绪耗时 | 原心跳间隔 | 新心跳间隔 |
| --- | ---: | ---: | ---: | ---: |
| 历史首次打开 | 857.5 | 683.0 | 116.3 | 122.5 |
| 历史下一页 | 469.9 | 393.9 | 56.7 | 67.1 |
| 历史上一页 | 153.4 | 129.6 | 21.1 | 20.4 |
| 规则首次打开 | 463.1 | 383.5 | 234.8 | 161.1 |
| 规则再次打开 | 450.7 | 360.8 | 223.2 | 165.0 |
| 规则第二页签 | 85.5 | 82.7 | 37.2 | 32.1 |

规则打开约快 17%–20%，主线程停顿也下降。历史打开和翻页耗时约下降 15%–20%，但下一页心跳间隔没有下降，仍存在布局绘制开销，不能宣称所有界面操作都已经完全流畅。更大批次方案的停顿问题已收紧，最终每张卡片后均让出事件循环。

详情宝物区域仍有大量原生 Label 创建和首次布局开销，后续可评估 Canvas 合并绘制或视口加载；本轮保留其完整展示行为。原始结果及汇总见 `artifacts/ui-performance/optimization-final-*.json`。
