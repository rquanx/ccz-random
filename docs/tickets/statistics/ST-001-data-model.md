# ST-001 统计数据模型与历史迁移

## 目标

扩展现有 SQLite 历史数据库，使统计模块能够区分运行、轮次、尝试和最终保留结果。

## 范围

- 新增或迁移 `runs`、`rounds`、`attempts`、`result_members`、`result_treasures`、`result_skills`、`result_treasure_properties`。
- 保存稳定 ID、显示名称、工具版本、规则版本和枚举版本。
- 保存规则名称、规则 schema 版本、规则配置指纹和完整规则快照。
- 规则指纹使用规范化规则 JSON 的 SHA-256。
- 保留旧版 `snapshot_json`。
- 为旧数据标记 `schemaVersion = 0`，缺失字段填充未知。

## 关键规则

- `attempt_id` 独立于存档编号。
- 最终结果由 `save_confirmed = 1` 且 `published = 1` 标识。
- 循环中间结果默认不标记为最终结果。
- 同一个 `run_id + round_id + slot` 最多一条最终结果。
- 同名但配置内容不同的规则必须产生不同 `rule_snapshot_hash`。
- 原始快照和查询索引必须可以相互校验。
- 迁移失败不能阻止工具启动。
- 数据库字段名必须与实现保持一致：运行规则快照字段使用 `runs.rule_json`；
  文档中的“规则快照”是业务含义，不得另建同义字段。
- `attempts` 通过 `round_id -> rounds.run_id` 关联运行，不重复保存 `run_id`。
- `(round_id, slot, attempt_number)` 必须有唯一约束或等价幂等保护。

## 验收标准

- 旧历史数据库可以正常打开。
- 迁移重复执行不会重复插入数据。
- 旧版只有最终结果的数据不会被伪造出失败尝试。
- 一个存档多次尝试能保留多条尝试记录。
- 一个存档最终结果最多一条。
- 同名不同配置的规则记录不会被覆盖或合并。
- 技能和宝物特性索引可以从原始快照重建。
- 旧记录可以在统计页面显示，并明确标识数据不完整。
- 同一尝试重复写入不会产生重复统计记录。
- 最终结果只能有一条，并且必须同时满足保存确认和发布确认。

## 测试

- SQLite 临时数据库迁移测试。
- 重复迁移幂等性测试。
- 旧快照缺字段测试。
- 唯一约束和外键约束测试。
- 查询字段和时间字段索引测试。
