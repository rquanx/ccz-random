# 2.2 招募支持

## 第一版范围

- 当前版本只支持 2.2，固定初始三人模式。旧版 2.10 已独立保存在 `stable-2.10` 分支。
- 使用 2.2 在许子将处配置并保存的第 20 栏作为源存档。随机合格后直接保存结果，不再插入招募模式选择。
- 保存流程会进入首关并追加部分剧情天赋，所以在保存完成后采集招募数据。每份结果独立保存该次随机的数据，无需依赖仍在运行的游戏。
- 从主界面“查看招募结果”进入历史记录，打开存档详情，再点“查看本次全部招募候选”。初始三人继续使用摘要卡片；大量候选使用可滚动表格、关卡筛选、姓名/兵种/天赋搜索、Ctrl/Shift 多选关注及“只看关注人物”。关注选择仅作用于当前窗口，不改变合格规则。
- 展示 42 个关卡招募窗口、116 名去重候选（126 条关卡人物关系），保留红蓝路线及重复出现的招募机会。候选不等于全部能在同一周目招募；仍受路线、15 次招募额度和特殊人物互斥约束。

## 数据来源与例外

真实 2.2 游戏内置 `RS/R_99.EEX` 中的“可招募人物根据关卡赋值”块提供关卡到人物索引的映射，`Imsg.e5` 提供关卡名称。目录位于 `resources/data/recruitment/recruits_2.2.json`，记录原始脚本和文本资源 SHA-256。提取器和原始赋值块回归夹具用于防止猜测招募关系。

普通候选的未来兵种读取预生成表 `0x00503F40`，不能使用尚未加入的单位记录当前兵种。天赋沿用现有内存解析器，兵种天赋按未来兵种解析，人物天赋按人物索引解析。

205–209 五名彩蛋女武将使用固定配置，不套用预生成兵种表。招募时可选兵种的武将单独标明选项；当前展示为招募前预览，选择其他兵种后的天赋和特殊招募时的配置调整不属于这份快照的最终承诺。第一版不模拟后续所有剧情对天赋、装备的修改。

## 后续扩展

1. 先将“关注人物”升级为可持久化的候选名单，仍与合格规则分开。
2. 为初始三人与候选统一提供按人物索引选择的规则目标，支持“全部达标 / 至少 N 人达标”。
3. 评估候选组合时加入红蓝路线互斥、招募消耗、女武将互斥及可选兵种，不将所有候选误算成同一支可实现队伍。
4. 对可选兵种分别计算天赋方案，增加后续实际招募的对照验证，再开放任意人员筛选。

## 验证方式

快速测试使用真实脚本块、真实招募开启前后状态片段、真实随机后内存读取记录；不需要启动游戏。完整单元测试：

```powershell
.venv-win10-py314/Scripts/python.exe -m unittest discover -s tests/unit
```

真实冒烟只在临时游戏副本中运行，使用宽松诊断阈值确保完成一次流程，不改变用户规则文件：

```powershell
.venv-win10-py314/Scripts/python.exe -m tools.diagnostics.smoke_recruitment_22 --game-dir 'E:/game/ccz/曹操传加强版2.2' --output .tmp/recruitment-smoke
```

它验证随机、首项招募模式、116 人快照、真实存档与回读后一致性，并校验源第 20 栏存档和源 S_00 脚本未改变。没有逐关游玩验证所有人物实际招募，也未验证其他修改版的相同文件名兼容性。
