# 高编号人物不能使用仙桃、仙酒：引擎调查

调查日期：2026-11-16。尚未修改正式游戏、存档或随机工具行为。

## 已确认的结论

2.20-1104 夜版存在引擎内的编号限制，准确边界是**内部人物编号 >= 102**，不是 >= 100。100、101 能通过本项编号检查，但仍可能受出战状态等其他条件影响。界面编号是否从 1 开始应另行核对，不能直接与内部编号混用。

验证程序：`Ekd5.exe`，SHA-256 `aece85339ff48c24e8d783d2d65766e8c9f7be00bd7389d38a8cad8f7cbd95a5`。其他版本尚未验证，不可套用地址。

仙桃、仙酒的运行时道具记录分别为：

| 道具 | 道具编号 | 效果类型 | 参数 |
| --- | --- | --- | --- |
| 仙桃 | 167 | 0x2A | 25 |
| 仙酒 | 168 | 0x2B | 8 |

道具表位于 `0x4A1140`，记录长度 25 字节。参数来自实际运行时数据，不根据道具说明文本推断。

## 引擎证据

`0x4224D4` 为相关道具的使用处理流程。它先选择人物，再调用 `0x4224A8` 获取成长记录；失败则显示 `0x48B85C` 的文字“不能在这里使用。”，并跳过后面的道具消耗和属性增加。

`0x4224A8` 的关键指令：

```asm
004224AB  cmp ax, 66h
004224AF  jae 004224CE
; 正常使用还检查人物记录 +0x2A 是否为 FF
004224C3  imul edx, eax, 0Eh
004224C6  add edx, 00508400h
004224CC  jmp 004224D0
004224CE  mov al, 0FFh
```

`0x66` 为十进制 102；每个人的成长记录为 14 字节，包含七个 16 位数值。现有访问范围为 `0x508400` 到 `0x508993`。

仙桃、仙酒不仅修改人物本体属性，还在 `0x42258C` 执行：

```asm
add word ptr [ecx + edx*2 + 0Ah], ax
```

这里 `ecx` 是此前取得的成长记录，`edx` 分别为 0（仙桃）、1（仙酒）。因此它们会额外更新成长记录 +10、+12 的字段。

另外两处成长数据读写同样限制人物编号：

| 地址 | 行为 |
| --- | --- |
| `0x41055D` | `cmp ax, 0x66`，高编号返回 0，不读取成长补正 |
| `0x408B52` | `cmp ax, 0x66`，高编号跳过成长记录更新 |

所以只去掉使用时的拒绝分支不构成完整修复。

## 隔离运行验证

用项目现有沙箱功能建立独立游戏副本，在隔离桌面启动，直接调用该副本的原始 `0x4224A8`。调用参数 mode=1，排除“人物是否出战”的影响，只验证编号和记录寻址；没有执行道具消耗、修改人物或保存。

| 内部人物编号 | 返回 EAX | 成长记录地址 | 本项检查 |
| --- | --- | --- | --- |
| 99 | 99 | `0x50896A` | 通过 |
| 100 | 100 | `0x508978` | 通过 |
| 101 | 101 | `0x508986` | 通过 |
| 102 | 255 | — | 拒绝 |
| 143 | 255 | — | 拒绝 |
| 214 | 255 | — | 拒绝 |

本地调查产物在被 Git 忽略的 `artifacts/item-limit/`：`capture.py`、`probe.py`、`image.bin`、`probe-results.json`。其中脚本是本次调查工具，固定针对本机隔离副本和已验证指令，不是发布补丁。

## 可行的修复方向

建议做**游戏启动时加载的兼容补丁**，为高编号人物补齐成长记录。随机工具写完存档后会退出自己的游戏实例，仅在随机期间修改内存无法修复玩家之后单独启动的游戏。

完整补丁至少需要：

1. 核对当前版本人物总数，分配足够大的独立成长表，保留低编号人物原有数据。
2. 统一修正道具资格判断、成长记录寻址、成长补正读取和更新路径；查清初始化、读档、重开时的清理行为。
3. 查明成长表的存档读写机制。选择兼容的扩展存储方案，验证保存、重启、读档后增长值持续有效；旧存档加载必须能得到正确初值。
4. 所有补丁地址先校验游戏指纹和原始指令，版本不匹配则拒绝应用。
5. 在隔离游戏中验证 99、100、101、102、143、214 等边界与高编号人物，检查道具数量、HP/MP 上限、升级后数值、保存回读、重启回读及旧存档兼容。

不建议直接把三个 `0x66` 改成更大的数：现有代码会继续用 `0x508400 + 人物编号 * 14` 访问原表之后的内存，未确认该区域可用前可能破坏其他状态。也不建议临时交换人物编号，剧情、天赋和招募均依赖人物身份。

后续已补充独立成长表、属性重算、两种存储方式的重启回读，以及 DLL 自动加载原型验证，详见 [完整方案调研](consumable-member-solutions-2026-11-16.md)。仍未提供可供玩家安装的完整补丁。
